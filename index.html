使う順番

6段階で、確認しながら実装へ

最初から情報を一括入力しません。安全な作業範囲を先に確認し、必要なことだけを対話で決めます。

  1. 作業フォルダを指定

    LPを作るフォルダをCodexへ絶対パスで伝えます。

  2. セットアップを送る

    Codexが既存指示、構成、技術、変更状態を読み取り専用で確認します。

  3. LP実装を送る

    準備完了の応答を確認してから、2つ目のファイルを送ります。

  4. 対話ヒアリング

    テーマ、対象、CTA、内容、ブランド、デザインを確認します。構成、wireframe、visual direction、検証計画を読み、明示承認することが次の段階へ進む必須条件です。

  5. HTML/CSS/JSをレスポンシブ実装

    Step 4のプランを承認した後にだけ、Codexが作業フォルダへ編集可能なLPを実装します。

  6. Codexが確認URLを用意

    Codexがpreviewを起動してmobile／desktopを確認し、利用者には開くだけのURL、確認結果、残課題を返します。

見た目の考え方

「AIっぽい装飾」ではなく、案件の中身から決める

特定の色や表現を一律に禁止するのではなく、実在する商品・利用場面・ブランド・信頼材料に理由を持たせます。

案件ごとに参考を選ぶ

過去案件の固定レイアウトを持ち込まず、今回の対象とCTAに合う構造、視覚、interaction、trustのpatternを選びます。

根拠のある見た目にする

色、書体、余白、画像、形状を、ブランド、商品、顧客、実在素材へ接続します。架空の画面や実績は作りません。

装飾より理解を優先する

最も目立つvisualが価値や使用場面の理解を助け、CTAとproofの優先順位を崩さないか確認します。

実装前に判断を見える化

mobile-first wireframeとvisual directionを提示し、色やカードを足す前に読み順と信頼の作り方を承認します。

承認が境界

相談中に、勝手に実装を始めない

Codexは必要な情報を対話で確認した後、要件、構成、wireframe、visual direction、変更予定ファイル、検証計画を先に提示します。

確認するもの
・誰向けのLPか
・Primary CTAは何か
・sectionとproofの順序
・mobile 390px / desktop 1440pxのwireframe
・案件固有のvisual direction
・変更予定ファイルと検証計画

問題がなければ「実装開始」と明示承認
→ HTML / CSS / JS実装
→ mobile / desktop review
→ Codexがpreview URLと残課題を報告

安全・公開境界

不足情報を創作せず、公開は別工程

秘密情報を渡さない

APIキー、パスワード、不要な顧客個人情報は依頼文や作業フォルダへ含めないでください。

実在するproofだけを使う

価格、資格、実績、口コミ、期限が未確認なら推測せず、省略または要確認として扱います。

既存変更を守る

Codexは対象フォルダの指示と変更状態を先に確認し、無関係な変更を戻しません。

公開前に人が確認する

事実、権利、法令表示、リンク、端末表示を確認し、公開は必要な権限を確認して別途行います。

よくある質問

受取と利用について

Skillのインストールは必要ですか？

必要ありません。2つのMarkdownを順番にCodexへ送る方式です。ZIP内のSkill資料は任意の互換補助で、標準手順の前提ではありません。

2つのファイルを一度に送ってもよいですか？

順番に送ってください。最初にセットアップを送り、絶対パスと準備完了の状態マーカーを含む応答を受け取ってから、lp実装を送ります。

テーマやCTAを先に全部決める必要がありますか？

ありません。Codexが既存情報を確認し、不足する内容だけを1〜3問ずつ聞きます。Primary audienceとPrimary CTAは実装前に確定します。

自分でローカルサーバーを起動する必要がありますか？

ありません。特典ページはそのままブラウザで利用でき、LP制作時のpreviewもCodexが起動・確認します。利用者には開くだけのURLと確認結果が返されます。

この配布物だけで公開までできますか？

外部公開は含まれません。ローカル実装と確認後、事実・権利・表示・運用条件を人が確認し、別工程として公開してください。
